# Лабораторная работа №4 — Mesto

Вариант 1: интеграция с API и окно статистики карточки. Проект выполнен на основе [официальной заготовки Практикума](https://github.com/Yandex-Practicum/mesto-ad), сохранены исходная вёрстка, БЭМ-структура и HTML-шаблоны.

Репозиторий исходников: [flareopti/mesto-private](https://github.com/flareopti/mesto-private).
Репозиторий сборки: [flareopti/mesto-public](https://github.com/flareopti/mesto-public).
Адрес после включения GitHub Pages: [flareopti.github.io/mesto-public](https://flareopti.github.io/mesto-public/).
Публикация пока не выполнена: GitHub отклонил локальный SSH-ключ (`Permission denied (publickey)`).

## Запуск

Нужен Node.js 22.12 или новее. Из каталога проекта:

```sh
npm ci
```

Для нового компьютера скопируйте `.env.example` в `.env.local` и заполните `VITE_MESTO_TOKEN`. На текущем компьютере файл `.env.local` уже подготовлен, повторно копировать пример не нужно.

```sh
npm run dev
```

Vite откроет приложение в браузере. Сервер доступен по адресу `http://127.0.0.1:5173/`; при занятом порте Vite напечатает следующий свободный адрес.

```sh
npm test
npm run build
npm run preview
```

`npm test` выполняет 11 интеграционных сценариев в jsdom с моделью API. `npm run build` создаёт production-сборку в `dist/`, `npm run preview` позволяет проверить её локально. В `vite.config.js` установлены `server.open: true`, `base: './'`, отключены source maps.

## Реализовано

- Начальная загрузка карточек и профиля через `Promise.all`, обработка ошибки и кнопка повторной загрузки. Предустановленных данных профиля и массива локальных карточек нет.
- Редактирование имени, занятия и аватара через PATCH-запросы. Данные на странице изменяются после успешного ответа API.
- Создание карточки через POST, добавление в начало галереи. Удаление через DELETE, корзина видна только владельцу; перед удалением открывается окно подтверждения.
- Постановка и снятие лайка через PUT/DELETE. Состояние сердечка и счётчик берутся из ответа API; повторный клик блокируется на время запроса.
- Полноразмерная фотография с подписью; заглушка для недоступных внешних изображений.
- Во всех формах отключена встроенная отправка браузера, есть сообщения валидации, блокировка невалидных данных и состояния «Сохранение…», «Создание…», «Удаление…». При ошибке введённые значения сохраняются.
- Закрытие модальных окон крестиком, кликом на фон и Escape, возврат фокуса, ограничение Tab внутри открытого окна.

Правила полей: имя — 2–40 символов; название — 2–30; оба поля допускают латиницу, кириллицу, дефис и пробел. Занятие — 2–200 символов. Ссылки на аватар и фотографию обязательны и проверяются как URL. Поле имени и название не принимают строку из одних пробелов.

## Вариант 1

Кнопка `i` запрашивает актуальный список карточек, находит выбранную по `_id` и открывает окно статистики. В окне показаны автор, дата создания, число лайков и имена пользователей, поставивших лайк. Дата преобразуется через `new Date` и `toLocaleDateString('ru-RU')`. Каждый новый просмотр повторяет запрос, старые строки и список пользователей очищаются. Для разметки используются только предоставленные шаблоны `popup-info-definition-template` и `popup-info-user-preview-template`. Значения вставляются через `textContent`.

## API и структура

База API: `https://mesto.nomoreparties.co/v1/apf-cohort-203`. Токен берётся из `.env.local`, передаётся в заголовке `authorization` и не записан в исходники. Каждый ответ проверяется через `response.ok`, запросы имеют тайм-аут 20 секунд.

| Модуль | Назначение |
| --- | --- |
| `src/scripts/components/api.js` | Все запросы API, без работы с DOM |
| `src/scripts/components/card.js` | Шаблон карточки, обработчики и обновление лайков |
| `src/scripts/components/modal.js` | Открытие, закрытие и клавиатурная навигация |
| `src/scripts/components/validation.js` | Универсальная валидация, экспорты `enableValidation` и `clearValidation` |
| `src/scripts/index.js` | Инициализация, обработка ответов, формы и статистика |
| `tests/app.test.js` | Интеграционные проверки успешных и ошибочных ответов |
| `.github/workflows/deploy.yml` | Проверка, сборка и отправка только `dist` в публичный репозиторий |

Учебный API возвращает общую галерею группы: названия, даты, лайки и внешние ссылки зависят от других студентов. Недоступность внешней фотографии не блокирует карточку и её статистику.

## Публикация

Исходный код размещается только в приватном репозитории, в публичный отправляется содержимое `dist/`.

После настройки SSH-доступа к GitHub:

```sh
ssh -T git@github.com
git push -u origin main
npm run deploy
```

Команда `npm run deploy` собирает проект и использует `gh-pages` для отправки сборки по SSH в `git@github.com:flareopti/mesto-public.git`, ветка `main`. Адрес задаётся переменной `PUBLIC_PAGES_REPO=flareopti/mesto-public` в `.env.local`.

В публичном репозитории откройте Settings → Pages → Deploy from a branch → `main` → `/ (root)`. После завершения публикации проверьте HTTPS-адрес сайта.

Для автоматического деплоя добавьте в приватном репозитории Settings → Secrets and variables → Actions:

- `VITE_MESTO_TOKEN` — учебный токен Mesto;
- `PUBLIC_PAGES_REPO` — `flareopti/mesto-public`;
- `PUBLIC_PAGES_TOKEN` — GitHub-токен, имеющий право записи в публичный репозиторий;
- `PUBLIC_PAGES_BRANCH` — необязательное значение, по умолчанию `main`.

Workflow запускается при push в `main` и вручную через Actions. Он выполняет `npm ci`, `npm test`, `npm run build`, после чего публикует только собранные файлы.

Переменные `VITE_*` встраиваются в клиентский JavaScript: при публикации сайта учебный токен Mesto будет доступен посетителям в сборке и сетевых запросах. `.env.local` исключён из Git; GitHub-токен публикации не передаётся в браузер и должен храниться только в Actions Secrets.

## Проверка результата

Автотесты проверяют начальную загрузку, права на удаление, начальные лайки, валидацию и сброс форм, ошибки сохранения, повторную отправку, обновление аватара, создание карточки после ответа, лайки, свежие данные статистики, безопасный вывод имён, открытие фотографии с клавиатуры и удаление с подтверждением.

В браузере проверены реальные GET-запросы профиля и карточек, открытие статистики, ограничения имени и отмена редактирования. На ширинах 360, 768 и 1440 px получены 1, 2 и 3 колонки соответственно; горизонтальной прокрутки нет. Данные профиля пользователя при проверке не изменялись. Проверка записи на реальном API заменена интеграционными тестами, чтобы не добавлять тестовые публикации в общую галерею группы.
